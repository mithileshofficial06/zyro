# Upstream SDK verification

A second pass over the official 1inch sources, this time the TypeScript SDKs in
[`1inch/sdks`](https://github.com/1inch/sdks). The build spec pointed at
`@1inch/aqua-sdk`, which does not exist as a repository — the real packages live
in the `1inch/sdks` monorepo under `typescript/aqua` and `typescript/swap-vm`.

This pass **independently confirms the opcode map** that
[`PHASE2-SOURCE-VERIFICATION.md`](PHASE2-SOURCE-VERIFICATION.md) derived from
the Solidity, and corrects one further spec claim.

---

## 1. The opcode map is confirmed by 1inch's own SDK ✅

`PHASE2-SOURCE-VERIFICATION.md` derived the Aqua opcode map by hand, working
through the `mstore`-over-element-0 trick in `AquaOpcodes._opcodes()` that
shifts the whole table by one. That derivation was load-bearing: if it were off
by one, Zyro would claim an occupied slot and quietly break a stock instruction.

It is now confirmed from a completely independent implementation.
`typescript/swap-vm/src/swap-vm/instructions/index.ts` exports
`aquaInstructions`, and `programs/program-builder.ts` turns an instruction into
bytes like this:

```ts
const opcodeIdx = this.ixsSet.findIndex((o) => o.id === opcode.id)
builder.addByte(BigInt(opcodeIdx)).addByte(BigInt(encodedBytes.length / 2))
```

**The numeric opcode is the zero-based array index**, and the header is the same
two bytes Zyro writes. Reading the indices off `aquaInstructions`:

| Index | Instruction | Zyro's value |
|---|---|---|
| 0–9 | `EMPTY_OPCODE` (reserved) | — |
| 10–16 | `controls.jump` … `onlyTakerTokenSupplyShareGte` | — |
| **17** | `xycSwap.xycSwapXD` | `OP_XYC_SWAP = 17` ✅ |
| 18 | `concentrate.concentrateGrowLiquidity2D` | — |
| 19 | `decay.decayXD` | — |
| **20** | `controls.salt` | `OP_SALT = 20` ✅ |
| 21 | `fee.flatFeeAmountInXD` | — |
| 22–26 | `EMPTY_OPCODE` (reserved) | — |
| 27–30 | `fee` protocol-fee instructions | — |
| 31 | `peggedSwap.peggedSwapGrowPriceRange2D` | — |
| 32 | `extruction.extruction` | — |
| 33 | `controls.onlyTxOriginTokenBalanceNonZero` | — |
| **34** | — (one past the end) | `OP_ZYRO = 34` ✅ |

The array has 34 entries, so `0..33` are taken and **34 is the next free
index** — exactly what Zyro claims, and exactly what `ZyroRouter.t.sol` observes
empirically when opcode 34 panics on the stock router and executes on Zyro's.

Three independent sources now agree: the Solidity, the official TypeScript SDK,
and a live test against a real `AquaSwapVMRouter`.

> Note the comments in `aquaInstructions` are 1-based labels (`// 18` sits on
> the entry at index 17). The index is what becomes the opcode, not the comment.

## 2. Neither SwapVM nor Aqua is published to npm ⚠

```
@1inch/swap-vm    404
@1inch/aqua       404
@1inch/sdk-core   0.1.3   ✅
@1inch/byte-utils 3.1.8   ✅
```

Only the shared utilities are published. The two SDKs that matter are
source-only, and they carry a non-OSS licence
(`LicenseRef-Degensoft-SwapVM-1.1`).

Consequence for Zyro: `packages/strategy-sdk` cannot depend on them, and stays
zero-dependency. Its correctness argument does not rest on matching their API —
it rests on byte-equality with the Solidity encoder, checked against fixtures
generated by a live `forge test` run. That is a stronger check than an API
match would be, and it is the one that would actually catch a divergence.

## 3. `order.data` has no token prefix — spec §20 is wrong ❌

§20 states that `order.data` is `tokenA(20) ++ tokenB(20) ++ program`. It is
not. From `typescript/swap-vm/src/swap-vm/order.ts`:

```ts
public build(): BuiltOrder {
  const { traits, hooksData } = this.traits.encode(this.maker)
  return { maker, traits, data: hooksData.concat(this.program).toString() }
}
```

`data` is `hooksData ++ program`, and with no maker hooks configured `hooksData`
is empty, so `data` **is** the program. This matches `MakerTraitsLib.build` in
the Solidity, which packs exactly the four hook slices followed by the program
and records their boundaries in the traits word.

Anything decoding a shipped Zyro position — the subgraph especially — must slice
the program at `MakerTraits.hooksDataEndsAtByte(traits)` rather than at a fixed
40-byte offset. A fixed offset would silently read 40 bytes of program as two
addresses and then mis-parse every instruction after it.

## 4. The strategy blob and the strategy hash ✅

§20's other claim holds: the `Shipped.strategy` blob decodes as
`(address, uint256, bytes)`. That tuple is precisely `Order.ABI`:

```ts
static ABI = { type: 'tuple', components: [
  { name: 'maker',  type: 'address' },
  { name: 'traits', type: 'uint256' },
  { name: 'data',   type: 'bytes'   },
]}
```

So **the strategy blob is an ABI-encoded SwapVM `Order`**, and

```ts
static calculateStrategyHash(strategy) { return keccak256(strategy) }
```

which is the same value `SwapVM.hash()` returns in Aqua mode
(`keccak256(abi.encode(order))`). The strategy hash and the order hash are the
same number, which is why `AQUA.safeBalances(maker, app, orderHash, …)` finds
the position. `ZyroRouter.t.sol` already asserts this hash is identical on the
stock router and on Zyro's — if it were not, every shipped position would be
orphaned by the upgrade.

## 5. Aqua's ledger events ✅

Confirmed against `IAqua.sol`:

```solidity
event Shipped(address maker, address app, bytes32 strategyHash, bytes strategy);
event Docked (address maker, address app, bytes32 strategyHash);
event Pulled (address maker, address app, bytes32 strategyHash, address token, uint256 amount);
event Pushed (address maker, address app, bytes32 strategyHash, address token, uint256 amount);
```

`Shipped` topic0, from the SDK:
`0xdc3622e06fb145651f567d421c9ef261d71d43e3778b761907bc0d70d42e52b0`

Two things the subgraph depends on:

- **`Pushed`/`Pulled` exist and carry `(token, amount)`**, so §20's Correction 6
  stands: position balances must be reconstructed from these, not accumulated
  from `Swapped` deltas on top of zero.
- **No parameter on any of these events is `indexed`.** Every field is in the
  data blob. A handler written expecting `maker` or `app` in `topics` will read
  the wrong bytes without erroring.

## 6. `buildShipTx` returns calldata, not a transaction ✅

§14's correction 5 is right. `AquaProtocolContract` is a stateless encoder:

```ts
static buildShipTx(contractAddress, params): CallInfo {
  return { to: ..., data: this.encodeShipCallData(params).toString(), value: 0n }
}
```

There is no `.ship()` that sends anything — the caller submits it with their own
wallet. `ship(app, strategy, tokens, amounts)` and
`dock(app, strategyHash, tokens)`.
